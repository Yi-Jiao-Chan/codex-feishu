## M0 必过项

现有本地 27 项协议断言可以复用，不用每个模块重新验证所有协议。以下三类尚待真实环境验证：

1. 真实 App：远程主会话、fork、worktree、子代理的分类与项目路径；第一条输入发现准确。
2. App 界面：外部输入在同一会话实时显示；忙时排队位置、显式引导后聊天记录正确。
3. 飞书：企业自建应用真实长连接、建群、Card JSON 2.0 渲染、回调、@ 与手机布局。

同时落实权限精确 ID、固定 SDK、更新卡片是否能触发提醒、建群/消息去重字段与有效期。证据不足的能力不标 pass。

## 验证环境与证据

测试分三层：领域边界（目录/时间）、协议与故障注入（双客户端、掉响应、崩溃）、真实 App/飞书 UI。测试要证明行为和失败恢复，不只断言模板函数返回某常量。

使用本人测试应用/群和独立临时目录；真实外部发送需要对应任务已授权。mock 模型控制轮次时序，避免依赖真实模型“刚好生成很久”。App 实际来源/回显与真实飞书提醒另做人工/工具验收，不用模拟替代。

故障注入点至少覆盖：RPC 发出后丢响应；远程成功本地落盘前崩溃；delete 和 steer 之间结束轮次；App 同时消费队列；消息/群创建超时；飞书限流后用户切 off；topic root 失效。

每份报告记录：工具 commit、CLI/daemon 版本、schema 摘要、SDK 版本、主机/用户、案例编号、结果、远程标识与脱敏证据路径、未通过项。示例：[验收报告模板](examples/acceptance-report.template.json)。截图只用于必要的布局/UI 证据，凭据不可出现在其中。

当前 CLI 的显式 acceptance-report 入口已提供只读身份/证据核验与结束判定，具体输入见 10 和 Agent 指南。人工报告真实性与案例覆盖由验收者审核，CLI 只核验记录、当前诊断及文件摘要；自动测试通过不生成真实 UI pass，报告核验成功也不自动发布。

protocol_schema_digest 指向固定兼容语料：本机 0.162.0 的 `app-server generate-json-schema --experimental` 输出 447 个 JSON；按相对 POSIX 文件名排序，将每个文件 SHA-256 写成紧凑 JSON 对象，再对对象字节作 SHA-256，结果为 `4248c44d68df2d0d55be53b15fffbb24d8c8cf41cb9993a1f79d5d03d3d2b5da`。2026-10-12 重新导出与先前实际语料一致，ThreadStartParams 摘要也与已有协议研究一致；导出不启动 daemon 或任务。该摘要是构建兼容依据，运行时仍核验实际 daemon 版本，不冒充实时 schema 探测。

## 发布内容与门槛

一期发布包包括：二进制与校验和、版本元数据、Codex 兼容清单、飞书精确权限清单、配置样例、Agent 配置指南、用户服务模板、诊断和验收记录。发布前将本手册/配置指南的“尚未实现”状态更新为真实版本，并用实际 --help / --json 核对命令契约；没有二期时 creation 开关不可启用，不能显示话题/创建按钮。

通过全部 P1 必需项后发布一期；P2 项全部通过再开放二期。仅有局部协议通过时发布为开发验证版本，并明确缺项，不能让配置 Agent 把它当完整可用版本。

P1-11 / P1-12 的真实安装验收可使用显式候选路径：二进制声明 `candidate_deployment=true`，按 Agent 指南使用 `setup --candidate-test`（显式配置/数据库）和 `service install/start --candidate-test`。这样可以在 `phase1_released=false` 时验证真实交付命令，避免“先发布才可安装、先安装验收才可发布”的循环。候选模式不提升 UI 或 P1 状态，不授权 M0 接管/迁移，不替换活动部署；默认安装门槛保留。隔离测试只验证命令行为，真实服务、App/飞书页面、注销与重启条件仍需单独取证。

最后审阅实际 diff 与证据：同一线程、默认排队、明确引导、一次投递与免打扰是否真正达成。成功验证无需无理由重复；新增改动或失败只补受影响检查。

当前本地 development 验收包已提供显式白名单、源码 / 二进制 commit 核验、归档与成员校验和、兼容 / 权限清单、指南、服务示例和全部 12 项 P1 pending 模板。它不改变 `phase1_released`，不代替受控真实测试或来源可信的正式发布。服务示例只说明生成结构；实际安装必须使用已验收 CLI 或显式候选路径的 service install，不能直接复制占位 unit。打包与真实安装 / 升级验收分开记录。

当前管理实例已有本人测试卡组件验证，走原接收器与持久请求记录，不新开连接。它只证明送达、实际 owner 回调和私聊入站；组件 observed 仍不提升 P1-10 / P1-11 或完整一期。管理测试群组件已有隔离验证；受控线程与真实服务部署继续 pending，详见[管理测试卡进展](../research/m3-managed-card-verification-2026-10-12.md)。
