# 管理通道、状态核验与离线取消进展

2026-10-12。开发集成，尚非一期发布。没有替换旧 M0 listener、迁移其数据库、安装正式用户服务或发送实际飞书消息 / @；用户今晚无需操作。fork 继续按 TODO 暂缓。

## 管理通道和健康

新版 serve 先持有应用 / 数据库锁，再打开仅同系统用户可访问的 Unix socket。位置按应用稳定计算，独立于配置 / XDG / 数据库别名；私有目录 0700，socket 0600，双方核验 Linux SO_PEERCRED。只接受版本化的 health 方法；没有原生 RPC、任意命令、消息发送或正文入口。字节数、并发连接和超时有上限，关闭取消等待并仅清理自己的 socket。现有 endpoint 只有确证 ECONNREFUSED 且 inode / 权限仍相符才替换；未知或活动 endpoint 不接管。

健康请求绑定物理配置路径和完整运行配置摘要。改变配置但未重启会返回冲突，不能用旧进程证明新配置生效。状态取现有飞书 receiver、当前原生客户端 reader 的 Done 和当前代际已核验的绑定。即使 Runtime 仍在等待 actor 退出，底层 reader 已断开也不显示连接 / 启用按钮。

status 优先查询匹配的运行实例和聚合持久记录。当前未解决的远程 unknown、仍未核验的请求和未确认的变更不会通过 operations_known，覆盖输入、原生动作 / attempts、mirror / attempts、命令回复、reaction、建群、任务控制及提醒日志。由观察证据终结的原生动作保留不可变 unknown 审计，同时记录有效待核验数；不能将已解决的历史记录当作永久故障。正常已接收 / 排队不因此判异常；前台实例无需凭空存在 systemd unit。服务安装、自启动、linger 条件单独列明。M0 无该通道时保持只读快照，实时连接 unknown / pending，退出码 5；不迁移旧库、不另开事件连接。该健康结果不是一期完整验收。

## 离线取消和停止队列

真正从未提交的 received 项可以在引用原消息的卡片点击“取消待提交”。操作者、绑定、真实远程卡 ID、token / revision、receipt 状态和全部历史写入日志在同一短事务检查；任一原生 attempt、M0 写入、历史关联或未决动作都禁止本地取消。取消保存 local confirmed 动作、修改原收据并更新同一张卡，重放不发 RPC。取消与原生提交竞争只有一个赢家，恢复 / 重启后被取消项不 add。

离线 mirror 投递仅在 nativeLoop 的串行空档执行：旧 Runtime / actor 已 join，下一代恢复未开始。退避期间周期处理后来的输入，deadline 不延后计划重连时间；常驻收消息 / reaction 循环不领取 mirror。没有历史水位时仍可发送固定状态的本地取消卡，引用已确认原输入关系。

已验证 interrupted 的队列显示“队列已保留，等待显式继续”；只有可靠活跃轮才提供追加引导。原生队列 DTO 没有 paused 字段，活跃轮也不能证明队列未暂停，所以一般排队卡不承诺自动启动。add 保持原生入口，继续仍须显式 start，不因卡片改变执行语义。

## 验证与剩余工作

自动测试覆盖实际 Unix socket 查询、配置冲突、无效方法 / 大请求 / 多余字段拒绝、错误脱敏、陈旧恢复、替换路径保护、时间过期与退出清理；服务级 fixture 覆盖退避中新增输入、实际引用卡、取消及同卡更新、恢复后零提交和单 receiver。取消模块还覆盖原生领取竞争、重放、跨身份篡改、回滚和 reopen 后 Controller 不发写 RPC。健康覆盖所有实际日志、部署隔离、已解决历史歧义和 schema 1–9 的只读兼容；读取不改变 user_version 或 0640 文件权限。
