# M3 通知配置事务与恢复（2026-10-12）

当前已有用户通知规则的 setup 更新已完成开发实现及本地测试。正式发布仍保留 `phase1_released=false`，没有对运行中的 M0 配置、数据库或进程进行切换。此次没有发送飞书消息、创建群、@ 用户、输入实际 Codex 会话或安装服务。

## 功能

- 计划冻结现有规则、完整 before/after 状态、数据库版本及配置摘要；未提供 quiet/timezone 保留有效值，明确空 quiet 清除本人免打扰。
- 仅修改 owner 明确提供的 quiet/timezone，保留 off/snooze，其他接收者保持原值。
- 规则更新要求私有准确 schema 9 数据库及匹配 host/app；不创建或迁移数据库。旧 M0 schema 1 仍需另行迁移、接管绑定与真实验收。
- 所有变更与恢复均持有配置、应用、数据库监听锁。配置没有变化但规则存在差异时也正常应用，且不替换配置 inode。
- SQLite 完整状态 CAS、批量事务和同事务审计：全 before 才提交，全 after 识别重复；混合或其他状态拒绝。不重复增加 revision 或审计。

## 恢复协议

已有规则更新先保存数据库旁的部署标记，再保存配置 prepared 日志与所需备份；原子替换配置后提交 SQLite，最后保存 applied 并清理部署标记。标记位置使用物理数据库路径，配置副本、备份、父目录和文件 symlink 别名不能绕过未完成事务的启动检查。

中断返回 `setup-recovery-pending`，保留原输入、plan_id、二进制、密钥、备份和事务文件，重跑原 apply 向前恢复。事务中断期间不启动桥。完成的历史日志不限制用户后来通过正常命令修改规则；重跑旧 apply 遇到后续用户变化则拒绝覆盖。

新格式日志冻结原计划的规则快照与数据库版本，并复算原 plan_id；删除规则变更、快照、版本或必要备份引用不能误判为已完成。旧 Version 0 纯配置日志继续保留恢复兼容。临时 socket 不参与新计划的授权摘要，兼容版本 daemon 重启后原计划可恢复，输入、artifact、凭据和兼容性仍受核验。

部署标记写入后、配置日志写入前的中断也仅允许原配置和原计划继续；如果其授权前提已改变，保持待恢复状态，需恢复原前提或后续单独设计的显式取消流程，不能删除状态强行启动。

## 验证范围

测试仅使用临时目录、模拟 Probe 与隔离 SQLite；包含以下实际故障注入：

- 部署标记、prepared、配置替换、数据库提交、applied 后五个边界的中断恢复，以及 daemon socket 变化后的恢复。
- SQL trigger 模拟写失败，检查数据库规则与审计整体回滚；原计划恢复成功，新计划不能覆盖未完成事务。
- 规则单独更新、重复应用、配置 inode 不变、off/snooze 精确保留、其他接收者不变、明确清除与省略字段。
- 并发规则变化、部署身份和 schema 错误、混合批次、第二接收者写失败以及 overflow 的拒绝。
- 删除日志变更/快照/版本/备份字段、未知字段、改变输入授权的拒绝；错误不泄露日志正文。
- 运行锁冲突阻止规则更新及提交后恢复；serve 在连接与迁移前拒绝未完成/损坏事务及变化的配置身份。
- 备份/复制配置和数据库 symlink 别名启动检查；完成后清理部署标记并允许正常启动检查。
