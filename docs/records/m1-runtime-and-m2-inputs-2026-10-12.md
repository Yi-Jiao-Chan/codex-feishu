# 正式运行时、持久输入与目录规则

日期：2026-10-12。此切片接入内部组合根和持久输入控制器，仍是开发版本；没有部署新的飞书接收器，也没有把尚未完成的一期矩阵标为通过。

## 本次可评审的实现

`internal/app/runtime.go` 为一个已连接的原生代次提供唯一事件消费者。基线快照等待 RPC 时仍持久接收 `thread/started`，已有绑定按主机恢复；候选通过完整元数据、首条输入、目录范围和 mute 规则后才进入会话 actor。Fork 继续记录 TODO、不自动跟进。

每个 actor 串行保存完整公开历史、运行输入控制钩子并领取出站日志；不同会话可以独立工作。事件只合并为唤醒信号，不直接发送每个 delta。活跃事件按默认一秒合并，空闲会话保留十五秒历史补偿。每次处理重新核验实际目录与主会话身份；历史检查点采用 RPC 返回后的时间。

建群独立等待，公开历史落盘继续进行。拿到实际 chat ID 并持久绑定后，原有出站日志补齐人类首条、过程和最终结果。创建结果未知或明确拒绝时冻结该意图，不创建替代群。退出一个原生代次时先取消并等待所有 actor、扫描和建群步骤结束，再允许上层替换连接或恢复 dispatching 日志。

`internal/submissions` 复用原始收据和稳定 client ID。普通输入只用原生 queue/add；本地卡片动作落盘后才由 actor 处理原生 RPC。追加引导保存原始目标轮次，删除确切队列项，只有确认删除才 steer；明确拒绝后，在没有队列/历史相关证据时以独立日志阶段恢复原输入。未知 add、delete、steer、restore 不盲重试。

停止捕获实际当前轮次；追加输入保留原生停止后的队列，继续动作只在空闲且有队列时 queue/start。queue/start 的未知响应缺少可靠相关标识，保持待核验，不因看到另一个 App 活跃轮次就宣布成功。回调使用卡片原有 revision 和 queue ID，不能拿最新数据库值代替旧按钮值。

目录命令解析与存储支持 `/mute-dir PATH [--recursive]`、`/unmute-dir PATH [--recursive]`、`/mute-dir list`，物理路径及精确/递归规则分别持久化；存储验证 host/app 归属。路径只作为数据处理，支持带空格路径，不执行 shell 展开。解除 mute 不重新激活已排除的历史候选；已绑定会话继续同步。

数据库 schema 升至 6：v5 新增输入/动作/阶段日志，v6 新增目录规则。迁移测试将旧版本 fixture 恢复为实际旧表结构，再验证逐级迁移。现有真实 M0 数据库和监听二进制未被升级或替换。

## 验证与边界

运行时并发测试覆盖：快照等待中的出生持久化、慢建群期间最终结果保存、实际人类镜像作为回复 parent、首次基线不建旧历史群、多会话路由、事件洪流合并、单会话处理不重叠、断线时等待所有工作结束，以及 mute 对未来候选/既有绑定的不同作用。

输入测试覆盖手册 Q1–Q10、App 在 delete 前消费队列、delete 后结束轮次、丢 add/steer/delete/restore 响应、保存阶段后重开数据库、RPC 前本地失败与成功后本地保存失败、并发冲突回调、错误部署/群的收据，以及未完整分页的历史。未知结果只根据确切相关证据核验。

这些是本地 SQLite、模拟原生双客户端和网关的故障测试，不能代替新的正式接收器在真实 App/飞书的 P1 验收。已有 M0 真实 UI 证据继续有效，但不能据此宣称此次组合根已经部署。
