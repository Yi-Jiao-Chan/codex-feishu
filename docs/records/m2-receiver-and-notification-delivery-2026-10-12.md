## 本次实现

- Receiver 按部署 host 的实际群绑定路由，仅接收授权操作者在群内结构化 @ 机器人的文本。回调只做短时本地持久化，不等待 Codex / 飞书 RPC；事件重放保持原 receipt / client 身份。私聊、未绑定群和斜杠命令留给独立命令处理入口，不创建二期任务。
- 队列卡使用已有持久消息出站日志，首次调用实际 Reply API 引用原输入，后续更新原卡。卡片仅显示操作状态，不重复正文；闲置时立即进入会话的输入只需 reaction，不额外创建队列卡。桥接 UI 使用明确保留的 ui:queue 身份，不改变原生历史水位，也不向 Codex 传入 UI 身份。
- 引导 / 移除按钮携带真实队列 ID 和当时 revision；接收器核验操作者、host/app/chat/thread、token 与实际远程卡片 ID。迟到按钮拒绝，不替换为当前最新队列项；重复回调重放原操作结果。
- StopExpected 将卡片展示的 turn ID 持久冻结，操作处理时若 App 已结束或切换到另一轮则拒绝；实际 Interrupt 永远使用原捕获 ID。斜杠 Stop 保持处理时捕获当前轮的语义。
- schema 7 保存策略历史及事件 / 用户级提醒决策。首次完整历史同步后、建群与投递前冻结 completed / failed 提醒资格，包括通知关闭或目标列表为空的配置；重连不能增加目标。秒精度原生时间保守核验该秒内策略变更，off→on 不复活被抑制的事件。
- 投递前重验当前策略与实际群成员；成员 API 在 SQL 事务外执行，无法证明可达性时仅投递正文。实际带 @ 载荷在 RPC 前冻结到 attempt，基础正文保持不含 @。更新卡、历史重放、不确定结果不再触发提醒。
- 多会话运行时提供历史暂存 / 投递后反馈挂接点；原生输入操作与完整历史同步由同一 thread actor 串行处理。断开后所有旧 worker 退出，才允许下一代恢复日志。
