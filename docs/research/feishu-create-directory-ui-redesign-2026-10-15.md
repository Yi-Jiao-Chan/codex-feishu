# 飞书创建任务：目录选择 UI 与交互重设计

日期：2026-10-15。当前交付为研究、设计规范与可操作原型，未修改或部署运行中的创建卡。依据用户的真实截图与四项反馈，并核验飞书官方组件、VS Code、Fluent、Apple HIG、NN/g；不是依据浏览器 mock 宣布飞书体验通过。

**推荐：主创建卡保持简短，目录改为一个“查找优先”的选择视图；需要探索位置时切到同一视图的浏览模式。**最近项目、搜索和逐层浏览都保留，按当前任务呈现。搜索输入、状态、结果、选用操作在同一区完成，不再把三个表单和两处确认纵向堆叠。


**用户决策更新：2026-10-15 选择“浏览优先”，已完成候选实现与部署。以浏览视图为默认目录入口，最近项目和查找作为辅助能力；下文原研究推荐及研究阶段交付边界保留为方案对比，不覆盖用户选择。最新实现、测试、真实 API 与待客户端验收边界见[实施记录](feishu-create-codex-session-implementation-2026-10-15.md)。**

配套证据：[飞书平台约束](feishu-directory-card-platform-ux-2026-10-15.md)、[成熟交互模式对标](feishu-directory-picker-patterns-2026-10-15.md)。本文件中的行数、容量和时延目标属于待验证的本项目设计，不能当平台承诺。

## 1. 实际问题与处理

| Before | After | Why |
| --- | --- | --- |
| 所有动作沿用 `cards.Button` 的 `text/small`，按钮像普通文字 | 查询、上一级、返回用 `default/medium` 描边；唯一主要确认用 `primary_filled/large` | 原生 v2 支持这些类型。创建卡需要可见的操作边界；不能照搬队列卡的低强调文字按钮 |
| “选择”“浏览子目录”“选用当前目录”“选用此路径”同时出现 | 查找结果旁直接“使用”；浏览只“进入”，唯一“使用当前目录” | 每个动作有固定对象，选目录只更新草稿，创建仍是主卡的独立动作 |
| 搜索在长卡底部，结果和确认又出现在上方 | 搜索框在结果前，结果旁选用；成功直接回主创建摘要 | 输入、反馈和操作就近，不依赖客户端自动滚动或悬浮工具栏 |
| 每页固定 10 项，少量目录也反复翻页 | 小量一次给全；大量先用有界下拉承载并可查找完整当前层；容量溢出才出现后续入口 | 10 项是应用选择，不是飞书限制。增加可见行数不能以撑高数屏为代价 |
| 只弹短暂“已收到”，卡片迟迟不动 | 同一区域持久呈现正在查找/打开/保存，完成后显示结果或错误 | 受理、处理中、已完成是不同事实；不能让用户靠反复点击判断系统是否工作 |
| 当前路径、完整路径、面包屑和路径输入重复占空间 | 当前路径只展示一次；路径输入与名称查找共用一个明确范围的输入框 | 降低重复与歧义，保留完整路径、上一级和直接前往能力 |
| 每次选择目录都连带获取其他表单和远程元数据 | 浏览仅处理目录；任务、跟进选项由草稿保存；项目核验留在真实选择/创建边界 | 控制等待时延，避免一个 UI 动作串行等待无关 RPC |

根因位置：[通用 Button](../../internal/cards/cards.go)、[创建卡布局](../../internal/cards/creation.go)、[creation 回调](../../internal/app/receiver.go)、[1 秒轮询与串行 worker](../../internal/creation/manager.go)。这些问题来自当前实现；不是用户没有发现“正确点法”。

飞书 `primary` 是蓝色描边，`primary_filled` 才是蓝底白字；`large` 在手机为 48px，不能只把文案叫“主按钮”而继续生成小号 text。[官方按钮字段表](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/interactive-components/button.md)

## 2. 推荐信息架构

### 主创建卡：任务、已选目录、创建

```text
新建 Codex 任务

任务内容
[预填用户原任务，允许编辑                    ]

工作目录                                  [更改目录]
codex-feishu
/workspace/ai-tools/codex-feishu

▸ 跟进位置 · 新建专属群

devbox                                     [创建任务]
```

主卡只有一个高强调动作“创建任务”。可靠的最近目录可预填；无合法默认时明确要求选目录。完整路径可识别，跟进方式不常驻占据两行下拉框。长正文沿用完整保留和可编辑长度边界，不截断、不在切换目录时清空。

### 默认选择视图：查找优先

```text
查找并选择目录 · devbox

项目名或完整路径
[codex                               ] [查找]
名称查找已知项目和最近目录；完整路径可直接定位。

查找完成 · 2 个匹配目录

codex-feishu          Codex 项目             [使用]
/workspace/ai-tools/codex-feishu
codex-feishu          Codex 项目             [使用]
/workspace/experiments/codex-feishu

[逐层浏览]                               [取消选择]
```

- 进入时展示真实存在的最近/已知项目；无数据时不伪造“最近使用”。项目名主行，完整父路径消歧，主机名只展示一次。
- 输入本身不发远程查询；点击查找或 Enter 才提交。查询和返回结果同时保留，不能把旧列表冒充新查询结果。
- 少量结果用分栏“名称/路径 + 使用”明确按钮；点击使用完成一次目录选择，成功回主创建摘要。目录视图不再设置第二个确认。
- 匹配较多时，将同一结果区换为有界原生下拉和紧邻的“使用所选目录”，不把几十行展开到卡片里。这个下拉用于容纳已返回结果；上方显式查找仍承担可验证的过滤，不依赖尚未核实的原生搜索。
- 取消保留任务和此前目录；浏览与查找切换应恢复先前查询。选目录不会建群、启动线程或提交首条输入。

这借鉴 VS Code Quick Pick 的短路径、标签/上下文和避免长向导，以及 HAPI 选择与创建分离的职责；不是把桌面 Quick Open 或 React 控件当作飞书现成功能。[VS Code Quick Picks](https://code.visualstudio.com/api/ux-guidelines/quick-picks)、[HAPI 固定提交](https://github.com/tiann/hapi/blob/5847b034e5cb84f2617766945c994b7905c5c03e/web/src/components/NewSession/index.tsx#L1474-L1486)

### 浏览次模式：先进入，使用当前目录

```text
浏览工作目录 · devbox

当前层名称或完整路径
[查找当前层，或粘贴完整路径           ] [查找]

当前位置                                  [上一级]
/workspace/projects

进入子目录 · 80 项
[选择一个子目录，直接打开                        ▾]
本层已载入 80 项；选择只进入目录。

[返回查找]                           [使用当前目录]
```

子目录下拉放在 form 外，选择即通过原生回调导航，删掉“选中后再按浏览”这一步。当前位置更新确认后才能使用；只读父目录仍可进入，下方文字解释不可选原因，确认禁用。没有子目录时明确显示空目录，可以使用已验证可写的当前目录。[官方单选回调](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/interactive-components/single-select-dropdown-menu.md)

本层查找过滤整个候选集，再应用返回预算，不能只筛选已加载的一页。输入完整路径时明确前往该目录；输入名称时限定当前层，不能暗示整机递归搜索。移动端用一个上一级按钮和可换行路径，避免一长排难以辨认的文字面包屑。

原型中的 80 项是虚构容量场景，不是已证明飞书客户端支持 80 项的发布结论。两种布局可比较，实际推荐将“查找优先”作为默认，浏览只在需要探索时切入。

## 3. 持续反馈与响应协议

| 动作 | 已受理/处理中 | 确认完成 | 失败与恢复 |
| --- | --- | --- | --- |
| 查找 | 在输入下方显示“正在查找 codex…”；保留输入与上下文，暂禁用冲突动作 | 同一区域显示本次查询、结果数和可选项；0 项明确无匹配 | 保留查询、原目录与任务；显示可理解错误，可重新查找 |
| 进入/上一级 | 显示“正在打开 projects…”；旧位置仍可识别，暂不让用户选用尚未打开的新位置 | 当前位置与子目录列表一起更新，显示已打开 | 保持原位置；读取超时可安全重试，不突然变成空目录 |
| 使用目录 | 显示“正在使用 codex-feishu…”；暂禁冲突动作 | 保存草稿后回主卡，持久显示“已选择 codex-feishu”及完整路径 | 留在选择视图，保留任务与旧目录，不显示创建成功 |
| 创建任务 | 使用原创建日志与真实阶段；按钮禁用，显示创建进度 | 群/线程/首条输入达到原确认条件才完成 | unknown 保持核验，不因 UI 急于反馈而重复创建 |

NN/g 的研究强调及时、持续的状态反馈及可判断的操作结果；短暂 toast 只能补充受理，不能代替卡片里的结果。[Visibility of System Status](https://www.nngroup.com/articles/visibility-system-status/)、[Progress Indicators](https://www.nngroup.com/articles/progress-indicators/)

**具体实施要求：**

1. 回调只做身份/令牌/revision/期限检查与本地持久领取，尽快返回具体的受理提示。官方期限为 3 秒；继续使用内部 2 秒上限。不能把平台响应期限解释成目录读取已完成。[回调协议](https://open.feishu.cn/document/feishu-cards/card-callback-communication.md)
2. 给目录交互增加提交后立即唤醒；1 秒 ticker 只作恢复兜底。目录查询不要排在可能耗时较长的建群/原生创建 RPC 后；只读查询可以单独受限处理，创建远程写仍沿用原唯一串行日志。
3. 减少目录视图无关的 workgroup / project RPC。目录结果允许使用 UI 元数据缓存，最终选择、项目归属与 native 创建前仍用当前事实重新核验。缓存不提供授权证明。
4. 每张卡只有一个有序的 UI 更新出口。busy 和完成视图带同一动作/视图代次，不能让较迟到达的 busy 覆盖完成，也不能让旧查询覆盖新路径。同步回调 card 与后台 PATCH 并行写同一消息存在先后风险，不能靠固定 sleep 猜顺序；优先让受理 toast 与统一持久 outbox 协调更新。[延迟更新规则](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/handle-card-callbacks.md)
5. 没有已核实的 v2 可控 loading 字段，就用真实共享 busy 状态、明确文字和禁用操作；不许演示后声称平台有同款 spinner。超过软等待阈值显示“读取较慢，原选择已保留”；读取最终超时后给可重试状态。只读查询超时与远程创建 unknown 分开处理。
6. 不编造完成百分比或剩余时间。可记录受理、busy 可见、结果可见的时间差；目标是缩短“没有任何反馈”的空档，最终预算由实测 PC/手机 P50/P95 决定。本轮没有采集新版真实性能，原型的 650ms/2200ms 只是演示延迟。

JSON 2.0 目前只支持共享卡，busy 更新会对同一消息的接收者可见；不能将其包装成“仅点击者可见的临时卡”。[v2 注意事项](https://open.feishu.cn/document/feishu-cards/card-json-v2-structure.md)

## 4. 目录多时的容量策略

不用“把 10 改成 100 个可见行”解决问题。可见面积、候选数和消息预算是三件事：

- 少量结果采用紧凑目录行；较多结果由静态下拉承载已返回的有界集合。
- 返回条数由当前客户端验证过的 options 容量、200 元素/组件上限和实际序列化请求字节共同约束。发送与 PATCH 都有 30KB 公开限制；设计预留余量，不能只数可见文字。
- 长路径不在 option label 和 callback value 中反复复制。可用短的服务端选项引用，并在该草稿/视图代次下解析完整规范路径；不能用会随重排变化的裸数组下标执行目录选择，也不能把索引值当授权。
- 明确显示“已载入 M / 共 N”；只有真正得到完整集合时才说全部。默认尽量减少分页，不能承诺所有真实路径长度下都无分页。
- 超出安全预算时，上方查找过滤整层后返回；必要时保留一个带范围和计数的后续入口。绝对路径仍能直达未知目录，无需翻过所有父级列表。

官方未给静态下拉数量上限和原生搜索保证；不能把未发现字段等同于确定不支持，也不能当无限制。先验证 20/50/100 项样本的 API、PC、手机滚动、截断和搜索表现，再定目标批量大小。[官方单选 schema](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/interactive-components/single-select-dropdown-menu.md)、[结构限制](https://open.feishu.cn/document/feishu-cards/card-json-v2-structure.md)、[消息 PATCH 限制](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/patch.md)

## 5. 视觉与原生实现对应

| 设计位置 | 原生组件/样式 | 约束 |
| --- | --- | --- |
| 标题与次要主机信息 | Markdown 正文/notation | 不加彩色大 header；避免把所有正文做成同号标签 |
| 输入旁查找按钮 | 顶层 form 内 column_set：input + submit `default` | 窄屏允许重排，不用 `flex_mode:none` 假装始终适配 |
| 少量结果 | 分栏的主名/完整父路径 + `default` 使用按钮 | 每行一个含义明确的动作；路径不以 tooltip 作为唯一获取方式 |
| 多项/进入子目录 | `select_static type:default` | 有边框；导航选择在 form 外接 action.option，确认选值按各自语义处理 |
| 唯一主要确认 | `primary_filled`、large/适当 fill | 不是 primary 描边，更不是 text；没有必需动作时不强塞主按钮 |
| 等待、完成、错误 | 同区域持久状态、已证实的图标/文字、disabled | 不依赖 hover、假百分比、未证实动画、sticky、自动滚动或自动聚焦 |
| 任务跟进设置 | 默认折叠 | 原值跟草稿保存；不让目录操作清空其他表单 |

原型的产品外观为近似布局，实际飞书字号、边框、下拉系统菜单与主题由客户端决定。视觉检查和模拟数据不替代真实组件验证。

## 6. 验收与交付边界

应让第一次接触的人完成任务，而不是先解释按钮隐藏在哪里：

1. 同名项目通过父路径选对；结果旁使用后就回主摘要，任务内容和跟进设置仍在。
2. 小量目录不分页；多目录查找作用于整个当前层；不能因为目标在后半段而必须连续翻页。
3. 查找、进入、选用各自有可见受理/等待/完成/失败；慢响应期间用户能知道当前动作且不能误建任务。
4. root/只读父级可以浏览，但不能被使用；可写子目录可以使用；范围外或不存在路径有保稿错误。
5. 手机与 PC 验证输入旁操作、下拉容量、长路径、触控目标、卡片更新后位置；任何一项不依赖预设“自动滚回顶部”。
6. 三种能力继续使用既有原生长连接，无新增域名/H5/OAuth；创建、queue/steer、原线程和权限策略不随 UI 改版改变。

本轮只新增研究/设计与对话原型；生产代码、配置与正在运行的服务未更改。

### 原型验证结果

已在浏览器完成 736px 浅色、320px 浅色触屏、390px 深色触屏三组检查，并人工查看默认、查询结果与浏览状态截图：

- 输入、按钮、长路径无横向溢出；操作按钮有可见边框，手机触控区与深色对比可辨认。
- 同名目录通过路径消歧；查找、使用目录有持续等待状态；选用后回主卡，修改任务或取消不会丢失原内容。
- 80 个虚构候选可在下拉中选择，整层查找能匹配后半段目标；没有固定 10 项翻页。无结果、无效路径、空目录和不可选父级均有明确状态。
- 浏览时选择子目录直接进入；可写子目录可以使用。只有主卡的最终创建动作结束演示，目录操作不会触发创建。
- 三组均无 JavaScript 错误；检查遵循减少动态效果设置。

以上验证只覆盖本地交互原型。飞书原生下拉容量、实际卡片更新顺序与时延、PC/手机真实体验仍待实施后的客户端验收；原型的系统下拉与模拟延迟不作为这些项目的通过证据。


## 7. 用户截图后的视觉修正（2026-10-15）

用户确认浏览优先功能可以，但不接受实际飞书样式。真实截图说明原生 form 默认 12px 间距、独立按钮拉满布局和常驻长路径/host ID 带来的密度问题；这一观察优先于之前浏览器原型外观。此次只调整 renderer，保持动作、草稿、最终路径与后端流程。

| Before | After | Why |
| --- | --- | --- |
| 次操作和主要确认均 large，独立按钮拉满整行 | medium + 明确 default 宽度，按钮放入 none / auto 分栏；主要确认仍实心 | 用真实原生布局约束按钮尺寸，不依赖独立按钮默认样式 |
| form 采用默认 12px 逐项间距 | 显式 8px，摘要列内 2px | 减少标签和内容之间不必要的空白 |
| 主卡常驻完整长路径、主机 UUID、“独立目录” | 名称突出，短父路径为灰色可展开入口；完整路径与主机在该处展开 | 保留准确路径的查阅能力和执行值，减少技术信息占屏 |
| “更改目录”“上一级”各占一整行 | 摘要右侧就近排列 | 使动作与对应目录建立明确关联 |
| 三行任务框，较长的目录说明与重复标签 | 两行起始文本框；子目录下拉用直接打开的占位词，计数简短 | 缩短默认卡片，保留多行输入和全部查询能力 |
