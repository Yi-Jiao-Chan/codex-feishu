# M3：私聊配对与 Agent 配置指引

日期：2026-10-12。配对已有开发实现并通过自动测试，真实飞书私聊 UI 尚待验收。完整一期仍未发布，`phase1_released=false`、`setup_pair_ui_verified=false`。本轮没有发送飞书测试消息、开启真实接收器、提交 Codex 输入、部署正式服务或改动现有 M0 数据库。

## 实现范围

`setup pair --input PATH [--config PATH] --timeout 300 --json` 接受专用部分输入，只要求 schema、应用和私有密钥文件引用；不要求已有 owner、项目目录或二进制信息。已有配置须与输入的应用、物理密钥引用及 owner 一致。返回真实发送者的 open_id 后，Agent 将其填入待审核的向导输入；配对本身不写配置，不替换 owner。

新部署持有应用锁，在机器人身份及临时接收器 ready 后才输出口令；只处理配对事件。已有正式实例通过同用户 Unix 管理通道处理配对，沿用唯一的飞书接收器；旧 M0 不提供此通道时还须取得数据库监听锁，否则退出冲突。临时接收器的所有退出路径均取消、关闭并等待结束，然后释放锁；不打开或迁移数据库、不连接 native 服务。

口令有 128 bit 随机性，有效期 1–300 秒，单个实例只允许一个活动请求。仅接受同应用的用户私聊、精确文本命令与未过期口令；已有 owner 时必须由原 owner 确认。群消息、其他应用、错误 owner、错误口令或到期请求不能认领。所有可识别的 `/pair` 文本在普通入站处理之前被拦截，不成为任务输入或任务卡片。

状态只在内存中，口令不写数据库、配置或普通日志。CLI 仅在第一条 `pairing-waiting` JSON 事件的 `data.pair_command` 输出口令；`paired` 终态只返回 owner 和请求状态。Ctrl+C、连接中断或开始响应丢失时按原随机 request_id 尝试清理。底层同 ID 重试不重置到期时间；终态无法再次取得口令。

管理通道新增固定的 pair.begin / pair.state / pair.cancel 请求；沿用双向 SO_PEERCRED、私有目录与 socket 权限、配置摘要身份校验、严格字段解析和资源上限。健康查询只声明 pairing_supported，不携带配对口令或任意任务输入接口。

## 验证证据

自动测试使用临时目录、真实本地 Unix socket、临时数据库和模拟飞书事件；没有把这些测试当成真实应用验收。

- 核心：随机口令、并发单次确认、TTL 边界、同 ID 幂等、活动请求冲突、终态清理、错误应用/群/owner/命令拒绝。
- CLI：托管模式没有第二个接收器或额外锁；临时模式只启动一个接收器并等待退出；旧数据库锁冲突、身份冲突、超时、取消、SDK 中断均返回非成功结果，终态不泄漏口令或密钥。
- 管理通道：错误配置身份不调用配对处理器；参数与未知字段严格拒绝；状态查询不返回口令；健康查询仍可用。
- 正式服务：群中的配对命令不被执行，owner 私聊可确认；单接收器，且没有新增输入、命令、receipt、native action 或 outbound 日志。
- 部分输入：新配置缺 owner 可用；私有密钥、路径、配置身份冲突检查；已有配置和身份保持原样。

独立检查发现并修复两项边界：开始请求已提交但响应丢失时也须取消原 ID；同 ID 用较短 TTL 重试不能因原到期时间较长被客户端误判。对应回归测试通过。

最终整仓 `go test -race ./...`、`go vet ./...` 与 `go mod verify` 通过。版本能力与[模块 10](../codex-feishu/10-cli-and-setup.md)、[Agent 配置指南](../codex-feishu/AGENT-SETUP.md)同步更新。
